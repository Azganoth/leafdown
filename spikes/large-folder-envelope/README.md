# Large-folder performance envelope

Evidence for issue #540. This directory and the probe mounts in `src-tauri/src/folder.rs`, `src-tauri/src/folder/watch.rs`, and `src/features/folder-context/perf-probe.test.ts` exist only on this branch. They are not meant to be merged.

The results were measured on Windows 11 with an Intel Core i5-11600K, 32 GB of RAM, fixtures on a SATA SSD, Microsoft Defender real-time scanning on, and WebView2 153. Every run used a warm file-system cache.

## Reproduce

Run everything from the repository root.

1. Generate the fixtures, about 390,000 files in total, and map them to a short root so paths match typical folder contexts:

   ```powershell
   node spikes/large-folder-envelope/gen-fixtures.mjs <dir>\fixtures
   subst L: <dir>
   ```

2. Backend scan, watcher, and drive-root probes (release build, `#[ignore]`d unless named):

   ```powershell
   cd src-tauri
   cargo test --release --lib --no-run
   $env:PERF_FIXTURES = "L:\fixtures"; $env:PERF_OUT = "L:\results"
   <test binary> --ignored --exact folder::perf_probe::perf_probe_scan
   $env:PERF_WATCH_FIXTURE = "L:\fixtures\deep-50000"
   <test binary> --ignored --exact folder::watch::perf_probe::perf_probe_watch
   $env:PERF_SCAN_PATH = "C:\Windows"
   <test binary> --ignored --exact folder::perf_probe::perf_probe_scan_path
   $env:PERF_OBSERVE_PATH = "C:\"; $env:PERF_OBSERVE_SECS = "30"
   <test binary> --ignored --exact folder::watch::perf_probe::perf_probe_observe
   ```

   `perf_probe_scan` also writes each name-sorted tree to `L:\results\trees` for the next step.

3. Navigator functions in Node's V8:

   ```powershell
   $env:PERF_TREES = "L:\results\trees"; $env:PERF_OUT = "L:\results\navigator-functions.jsonl"
   pnpm exec vitest run src/features/folder-context/perf-probe.test.ts
   ```

4. End to end in the app. Build a release binary under an isolated identity, so the real app's settings and recent items are untouched, with the WebView2 debugging port enabled:

   ```powershell
   pnpm tauri build --no-bundle --config spikes/large-folder-envelope/tauri.perf.conf.json
   node spikes/large-folder-envelope/drive.mjs L:\results\app.jsonl "open:flat-1000,expand:flat-1000,expandAll:flat-1000,filter:flat-1000,sort:flat-1000,watch:flat-1000,burst:flat-1000:1000,burstTxt:flat-1000:1000"
   ```

   Other steps are `burst:<fixture>:<count>`, `rapid:<a>+<b>+<c>`, `keys:<fixture>`, and `idle:<ms>`. The driver deletes and reseeds `%APPDATA%\com.azganoth.leafdown.perf` on every launch. Remove that folder, `%LOCALAPPDATA%\com.azganoth.leafdown.perf`, and `leafdown-perf.exe` afterwards. Keep batches under ten minutes.

5. Modified-time source comparison: `cargo run --release --manifest-path spikes/large-folder-envelope/mtime-probe/Cargo.toml -- L:\fixtures\flat-50000`.

6. Tables: `node spikes/large-folder-envelope/summarize.mjs [results dir]`.

## Results

| File | Contents |
| --- | --- |
| `fixtures.jsonl` | Entries each fixture holds |
| `scan-long-root.jsonl` | Rust scan per sort order, five runs, 140-character fixture root |
| `scan.jsonl` | Rust scan and plain enumeration, three runs, `L:\fixtures` root |
| `watch.jsonl` | Watcher events for single changes and bursts on deep-50000 |
| `navigator-functions.jsonl` | Navigator row, filter, and lookup functions in Node, median of seven |
| `app.jsonl` | End-to-end app measurements. Records before the second `launch` come from a run stopped by system memory pressure; deep-50000 and later records come from the reruns that follow |
| `scan-path.jsonl`, `observe.jsonl` | Read-only `C:\Windows` scan and 30-second event counts, with no paths recorded |
| `mtime.jsonl` | Modified times read from directory entries against a metadata call per path |
| `summary.md` | Tables generated by `summarize.mjs` |
